## Code-Review Findings

1. **Clearing shot eligibility is offered by UI but rejected by API** — `frontend/src/pages/BrewLogDetail.tsx:255-267` exposes “No eligibility” as `value=""`, while `app/routers/api_brew_log.py:262-268` rejects `""` because it is not in `_SHOT_ELIGIBILITIES`. This is an implementation/API contract bug for Alex + Finn.
2. **Spec-039 cleanup misses B08-created brew logs** — `app/routers/api_e2e.py:239-249` deletes brew rows by shot/idempotency/notes/taste prefixes only. UI-created B08 brew logs can have normal generated shot IDs/idempotency while still referencing synthetic Spec-039 bags/catalog rows, so cleanup must delete brew logs by synthetic bag/catalog lineage before deleting those parent rows.

Additional high-signal validation findings: `frontend/e2e/spec039-ui-data-freshness.spec.ts:178` calls protected `/api/brew-log/{id}` without Authorization, and E2E feedback generation is non-hermetic when real LLM keys are present.
